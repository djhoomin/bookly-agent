Bookly support agent01 / Thesis

Containment is the wrong north star.

The industry measures the share of tickets closed without a human. That pressure builds agents which confidently do the wrong thing rather than hand over, because an agent that refunds an out-of-window order closes the ticket and scores perfectly.

What I built toward instead

Resolution without harm, at a price that scales.

The agent proves it knows enough to act before it acts, and the expensive model is only asked for the turns that need one. Three decisions follow, and each is enforced in code rather than requested in a prompt.

The failure this prevents

A customer with two copies of Dune on one account, an ebook and a paperback. One is refundable, one is never refundable. An agent that guesses is right half the time, and the customer sees every miss.

Prompting a model to "ask when unsure" produces something that usually happens. Removing the code path produces something that always does. The system prompt is six lines as a result, and its shortness is the evidence: everything enforceable moved into code.

Key decision03 / Policy is code

A prompt is a suggestion. A function is a rule.

A prompt saying "only refund within 30 days" is advisory, and a model being helpful to an angry customer will find a reading of it that permits yes. This returns the same answer whether the customer is polite or furious, and it is testable.

age = (today - order.delivered_on).days
if age > RETURN_WINDOW_DAYS:
    return Decision(
        False, "outside_window",
        f"Delivered {age} days ago, outside "
        f"the {RETURN_WINDOW_DAYS}-day window.")

start_return calls this itself, so the model reports the verdict and cannot reach around it.

Every refusal has a code, not a mood

What I traded away

Flexibility. There is no path to a goodwill exception, which a real deployment needs. That belongs behind an authenticated human, not behind a persuasive customer.

Key decision04 / One cheap call, two jobs

Opus to read a database row is not a business.

Haiku 4.5 screens every inbound turn. The same pass picks the model for that turn and flags abuse or fraud signals, because both want the same cheap read of the same text.

Why a misrouted turn is survivable 
"I'd like to return my Dune"

  triage -> simple  -> haiku-4-5
  find_orders -> 2 matches
  agent asks which one          OK

The classifier called that simple and it is arguably complex. It did not matter. Correctness lives in the gate and the policy function, and both are model-independent, so routing is an optimisation, not a safety mechanism. A triage miss costs a less polished reply, never a wrong refund.

And the second job

Claimed authority to override policy is flagged fraud_signal, routed to Opus, refused by policy anyway, and written to abuse_log.jsonl with the message attached. A flag without its text cannot be reviewed.

The trace then answers the operating questions with no extra instrumentation: 92% resolved without a human, every eligibility decision carrying a policy code, outside_window ×3, fraud_signal ×1.
What the trace caught during the build

Four of eight turns were refusing customers without calling the policy function, deciding from the published prose instead. The gate sealed wrong approvals and left wrong refusals open. Fixed by adding a read-only check_return_eligibility, so there is an authoritative answer without attempting the action. Every refund decision now records a code, two previously invisible refusal reasons appeared, and it came out 24% cheaper: fewer round trips than reading prose and reasoning about it.

What I would change first, given a production context

Build the eval set from real transcripts. These twelve test failures I thought of, which is the weakest kind of test. A public adversarial set such as deepset/prompt-injections (662 rows, Apache 2.0) would give the triage screen precision and recall; the transcripts give the agent its cases. Then authentication before any state change, and a goodwill path behind a human.
