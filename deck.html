Bookly support agent01 / Thesis

Containment is the wrong north star.

The industry scores tickets closed without a human, so agents learn to act confidently rather than hand over.

What I built toward instead

Resolution without harm, at a price that scales.

The agent proves it knows enough to act before it acts. The model understands the customer; code decides. The seam is the design.

Automated decisioning, as banks and insurers run it: decide alone where risk is low, bring a person in where it is not.

Key decision03 / Policy is code

Don't prompt what should have been code.

A prompt is advisory. A function returns the same answer whether the customer is polite or furious, and it is testable.

age = (today - order.delivered_on).days
if age > RETURN_WINDOW_DAYS:
    return Decision(
        False, "outside_window",
        f"Delivered {age} days ago, outside "
        f"the {RETURN_WINDOW_DAYS}-day window.")

How the code gets written does not matter. What runs at decision time does.

Prose gets the same rule: a second model holds every general answer to the published text. Explain the policy; never extend it.

Key decision04 / Two cheap calls before the expensive one

Opus to read a database row is not a business.

Haiku picks the tier. Mistral, free, screens abuse and self-harm. Haiku keeps bookstore fraud.

Routing is an optimisation; correctness never depends on it. A triage miss costs a less polished reply and never a wrong refund.

The second job

A threat is logged and the eligible refund still goes through; tone is not policy. A self-harm signal gets fixed text, crisis resources and a person. No model answers it.

Traded away, and why it was worth it

A less polished reply on a misrouted turn, and abusive customers cost more because risk routes heavy. In return, 72% off the bill with no wrong refund in 24 cases and 40 phrasings.
